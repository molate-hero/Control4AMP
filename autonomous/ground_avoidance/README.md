# ground_avoidance 地面自动避障

本模块独立于 `manual_control` 和 `network_control`，只负责 RealSense 深度感知、合力法决策和可选的 ESP32 差速输出。

## 运行方式

默认 dry-run，只打印差速命令，不会驱动车辆：

```bash
cd /home/orangepi/CONTROL/autonomous/ground_avoidance
./scripts/start_ground_avoidance.sh
```

确认已经停止手动遥控、网页地面控制和深度预览服务，并且拆除车轮或确认环境安全后，才允许真实输出：

```bash
./scripts/start_ground_avoidance.sh --hardware --esp32-port /dev/ttyUSB0
```

## 算法行为

算法把图像中下部裁剪为感兴趣区域，并等分成左、中、右三个扇区，分别估计可通行距离，然后按下面的规则生成差速指令：

1. **可通行距离**：每个扇区取有效深度读数的 20 百分位数。超过标定上限（`invalid_depth_m`，默认 8 米）的读数按上限处理，视为“很远”；回波为零或有效像素占比低于 `min_valid_ratio`（默认 15%）时该方向判定为**未知**。
2. **地面剔除**：地平线以下的近处地面不是障碍物，但它的深度很小，若不剔除会把可通行距离严重低估，导致车辆误判前方被堵而不敢前进。算法按地面模型 `s_ground(y) = K / (y - horizon)` 识别地面像素并排除；剔除后某方向若只剩地面，则该方向判为畅通。详见下一节。
3. **正前方未知即停车**：中心扇区未知时无法确认前方安全，直接停车（原因显示“正前方深度无效，停车待确认”），不会盲目前进。
4. **前进速度连续递减**：前进速度只由正前方距离决定，从 `slow_distance_m`（默认 1.8 米）开始线性减速，到 `obstacle_distance_m`（默认 0.6 米）降为零，不存在“恒速逼近后突然急停”。
5. **横向绕行**：左右扇区的障碍物产生横向斥力让车辆绕行。侧方未知不产生转向力；左右信息相同或都未知时沿用上一次转向方向，避免无信息时反复反向。
6. **行驶中的转向受油门约束**：差速混合为 `left=throttle+steering`、`right=throttle-steering`，算法把行驶中的转向上限绑定为 `|steering| ≤ throttle × 比例`，比例在巡航值 `forward_steering_ratio`（默认 0.35）和最近值 `close_steering_ratio`（默认 1.0）之间按障碍距离插值。这样**内侧车轮最多降到 0、绝不反转**，避障表现为“弯行”而不是“边前进边甩头”，否则会猛转过头错过侧面开口。
7. **原地转向只在停车时**：只有当正前方近于 `obstacle_distance_m`（默认 0.6 米）、已经停车时，才放开到 `pivot_steering_limit`（默认 0.60）允许两轮反向原地转向更宽的一侧。该值刻意温和，避免在狭小空间旋转过快冲过侧面开口。转向平滑之后会重新做一次上限限制，保证油门骤降时内侧车轮仍不反转。
8. **转向平滑与方向切换余量**：对转向做一阶平滑（`steering_smoothing`，默认 0.25），减少深度噪声引起的左右急摆；停车原地转向时不平滑，保证第一时间给出最大转向。左右宽度接近时（差值小于 `turn_switch_margin_m`，默认 0.15 米）沿用上一次绕行方向，只有另一侧明显更宽才反向，避免在开口处左右反复而错过出口。侧向选择力也只在 `slow_distance_m` 以内才开始起作用，不会提前很远就起转。
9. **正前方判断带容差**：`obstacle_distance_m` 比较时加 5 毫米容差。深度是 float32，0.6 米常表示为 0.60000002，严格比较会漏判并造成“既不前进也不转向”的死点。

当前算法把相机正前方定义为默认目标方向：没有外部目标点时会自动向前行进。它**不会自动倒车**，但正前方近距离障碍时会停车并向左右剩余空间更大的一侧原地转向（输出形如 `D,-218,218`）。

## 地面标定

地面剔除依赖两个只与相机安装姿态有关的参数：地平线所在行 `ground_horizon_row` 和尺度常数 `ground_scale_m_row`。它们已经用现场数据标定为 `141.7` 和 `44.5`（480×270 分辨率）。

**相机安装角度或高度改变后必须重新标定**，方法是在水平平地、前方 2~3 米无障碍的情况下运行：

```bash
cd /home/orangepi/CONTROL/autonomous/ground_avoidance
PYTHONPATH=/home/orangepi/.local/lib/python3.10/site-packages python3 calibrate_ground.py
```

脚本会打印逐行剖面、拟合得到的 `horizon_row` 和 `K`，以及可直接填回 `AvoidanceConfig` 的两行参数，并逐行核对“实测深度 vs 地面预测”确认标定是否合理。

两个参数配置为 `None` 时会关闭地面剔除，退回固定 ROI 行为。

## 已知限制

- 细障碍物（如细柱、桌腿）：碰撞判断和间隙宽度共用 20 百分位数，细障碍物占扇区比例低于约 20% 时可能不被识别，需要改用“最小值做碰撞判断 + 百分位做间隙宽度”的两套指标。
- 死角与 U 型死胡同：目标力始终指向相机正前方且不自动倒车，进入封闭死角后可能原地摆动无法退出，需要卡死检测脱困或改用 follow-the-gap / VFH+ 决策层。
- 开口宽度下限：仿真显示开口宽于 0.6 米可靠通过；0.5 米时两个版本的“转弯—直行”策略都会碰撞，因为当前不生成显式路径、在窄开口里无法对准。要穿越更窄的开口需要引入 follow-the-gap / VFH+ 之类的决策层。
- 地面剔除假设前方是**水平平地**。上下坡、台阶或大幅俯仰时 `s_ground(y)` 会失准，此时地面可能被误判为障碍或反之。PX4 姿态补偿可缓解，尚未实现。
- 地面余量 `ground_margin_m`（默认 0.20 米）决定“多近算地面”。贴地很矮的障碍（如门槛、薄板）可能落入余量内被误剔，需要按实际场景调整。
